# 自维护版 1.1.72 实施准备

本文件保留最初实施计划。当前源码已实现 1.1.72 修复并通过回归和宿主副本验证；完成状态与限制见 `REVIEW-1.1.72.md` 和开发日志。

## 基线与版本

- 基于固定提交 `5e757260a0be055892b48ec520d451cc82e1c191`，保留原 MIT 版权和原作者署名。
- 开发阶段建议用 `1.1.72-dev.1`，正式交付使用 `1.1.72`，界面/说明中注明自维护来源，避免被认为是原作者发布。
- 完整保留可回退的 1.1.71 基线。本轮审查只新增 audit 和开发记录。
- 优先目标是已只读确认的 Windows 官方桌面 `0.2.1-rc.3`；Web 另列验证状态，不借用旧版兼容声明。

## 第一批：先修安全与数据完整性

1. A01：抽出统一的来源/凭据验证，Web 同源、桌面特殊来源、null origin、回环和非回环分别测试。
2. A02：清理并检测嵌套 profile 配置，恢复插件拥有的默认预设，保证停用/卸载后可新建会话。
3. A03：修复 hostFs 的 fd 方法及所属 fs 路由，验证文本/二进制识别、句柄释放和 sealed/unpacked 两种情况。
4. A07：唯一临时文件 + 同目标并发语义；注入 ENOENT/EPERM/写失败，确保旧文件和备份可用。
5. A09：规则写接口仅接受 POST，只读 GET 无副作用。

## 第二批：升级必须可靠且属于自维护版本

1. F01：更新仓库和来源作为明确配置；未配置自维护源时禁用覆盖式更新，不悄悄切回原作者 master。
2. 检测本地改动，取消隐式强制 reset；先形成可恢复备份，再允许切换版本。
3. A04：完整包清单含 lib/bin/client/presets/skills/scripts 等；临时安装树校验成功后再整体切换。
4. A06：区分 file 目录、file 归档、包管理器安装及符号链接，不跨 profile 改错包。
5. 为自维护仓库调整发布 workflow、下载元数据、包来源和变更说明。新仓库地址尚未提供，不提前填写。

## 第三批：实际宿主适配与范围策略

1. 只读提取/复制 `0.2.1-rc.3` 的必要宿主样例到测试夹具，在副本上验证补丁命中、幂等及还原，不直接对日常安装试写。
2. 审核 `{{cwd}}` 插值、预设字段/schema、工具解析、桌面 ASAR/重启等跨版本变更。
3. A05：把授权目标范围做成可验证的策略，覆盖字面 IP、域名解析、后续工具参数和失效情况，不能仅依赖关键词首步检查。
4. A08：实测 Node 与 Electron 内置 Node/SQLite 组合，再确定最低运行版本。
5. 原有技能文件作为待审查资源保留；不执行环境铺设或下载/运行演练工具来证明安装成功。

## 验证分工

| 环境 | 负责验证 |
| --- | --- |
| 当前 Windows 隔离目录 | 文件/路径语义、profile 配置、模拟失败、Windows 启动器、产物检查 |
| 云端隔离环境 | 纯逻辑与 SQLite 测试、模块加载、Linux 文件行为、包产物、可重复回归 |
| 独立 Windows 测试安装/虚拟机 | Electron/ASAR、权限、真实 Apply/Restore、重启、停用卸载后新建会话 |

自动化不以公网目标或真实凭据为夹具。最终验收必须包括故障回滚；云端通过不能代替 Windows 桌面端通过。

## 交付条件

- 每个确认缺陷有真实回归用例；修复后测试必须断言正确行为，不能继续以“缺陷仍存在”为通过条件。
- 原始 `audit/run-audit.mjs` 是基线审查探针，修复后应更新或保留为归档，而不是充当新版全通过的证明。
- 明确列出支持的宿主版本和未测环境；完整包能从干净测试 profile 加载，并能完整还原。
- 版本、界面、包来源、更新源和说明一致，保留作者署名。
- 先产出可审查的本地包、测试结果与变更清单；实际安装/发布属于后续步骤。
