## 已确认缺陷

### A01 / P1：演练台的回环地址判断绕过来源校验

位置：`lib/redteam/ui.js:1095`，特别是 `if (loopback) return true`。

模拟来自 `127.0.0.1`、`Origin: https://untrusted.invalid` 的请求时，原始来源校验返回 true。本机浏览器访问本地服务时，socket 对端通常也是回环地址，不能用它判断网页来源可信。

影响：`/redteam/api` 提供写配置、写数据等有副作用的操作，代码未在这条判断后再要求独立令牌。外部网页是否能实际送达请求还受浏览器、本地网络访问限制及宿主中间件影响；本轮确认的是接口自身的校验缺口，没有宣称完成远程利用。

修复：统一 Web/桌面的信任来源策略；桌面特殊来源使用明确的会话凭据，拒绝因回环对端而无条件放行。为写接口验证来源、凭据与请求格式。

### A02 / P1：卸载不清理真正使用的嵌套 profile 配置

位置：`lib/uninstall.js:37`、`lib/uninstall.js:46`、`lib/uninstall.js:76`。

`stripPluginFromPackage()` 删除 dependencies 和顶层 bundles/plugins，却没有清理 `dsh.profile.bundles` / `dsh.profile.plugins`。对模拟真实结构的对象运行后，依赖消失而嵌套加载项仍为 `dsh-purge`。

影响：重启后宿主仍尝试加载已移除插件；仅通过嵌套配置登记的 profile 也可能漏检。另需补测红队默认预设在停用/卸载后的清理，当前实现未看到相应恢复逻辑。

修复：检测和清理真实嵌套结构；覆盖 desktop/web、仅登记 bundles、依赖缺失及多 profile 情形；恢复插件自己占用的默认预设时保留用户其他设置。

### A03 / P1：文件系统封装缺方法，启动器检测失效并可能泄漏句柄

位置：`lib/extract-asar.js:151`、`lib/extract-asar.js:158`；调用位置 `lib/core.js:7174`。

`hostFs` 提供 `openSync`，但不提供 `readSync` / `closeSync`。`isTextShim()` 打开文件后调用不存在的方法，异常被捕获并返回 false，关闭文件时的异常也被吞掉。

隔离复现：对只有普通注释文本的 `dsh.ps1` 调用 `patchShim()`，得到 `skipped_binary`；不是启动器实际为二进制。

影响：启动器清理/状态/补丁相关逻辑错误，重复探测可能累积未关闭句柄。宿主仍在 ASAR 中时还需正确保持 fd 与所属 fs 实现的对应关系。

修复：完整提供 fd 路由，测试打开、读写、关闭和错误路径；不能简单把数值 fd 当作路径交给路径探测。

### A04 / P1：ZIP 更新漏掉随包目录，存在混合版本

位置：`lib/update.js:20` 的 `COPY_NAMES`；使用位置约 `lib/update.js:880`。

覆盖清单包含 lib/package/client 等，却遗漏 `presets`、`skills`、`scripts`。这些目录在 1.1.71 包中真实存在，并被 package 的 files 清单包含。

影响：通过 ZIP 覆盖升级时，代码和版本号变新，预设/技能/脚本仍旧；在无旧目录的目标中则可能完全缺失。此结论来自覆盖清单和调用路径检查，未执行真实自更新。

修复：以明确的完整包清单生成升级产物，先在临时目录验证，再切换；失败恢复整个安装树，避免先删 lib 后半途报错。

### A05 / P1：网络检查不能兑现文档所描述的 IP/解析范围限制

位置：`lib/net-scope.js:468`、`:473`、`:629`、`:633`。

当前函数会直接跳过 IP 字面量，不对域名执行 DNS 范围判定；只在代理第一步挂检查，没有 `tools/pre-execute` 检查。

隔离复现：包含攻击关键词的文档保留地址样例被识别为任务，但目标检查返回 null。未向样例地址发送任何流量。

影响：文档中的地区/IP 限制并未由这段门禁完整落实；初始文本检查也不能约束随后生成的工具参数。不能将这个模块当成网络隔离层。

修复：明确自维护版本的授权范围；使用经解析验证的目标判定，并覆盖重定向/后续工具执行等路径。自动化复现仅使用本地合成目标，不进行公网攻击验证。

### A06 / P2：`file:` 压缩包被当成目录

位置：`lib/update.js:262`、`:267`、`:324`。

`isLinkSpec('file:./dsh-purge-1.1.71.tgz')` 返回 true，随后 `resolveLinkDir()` 返回的是压缩包文件路径，计划器却把它当作可覆盖安装目录。

影响：本地压缩包安装后的更新可能发生 ENOTDIR 或目录定位错误。没有在真实 profile 上运行升级。

修复：区分本地目录和本地归档，归档安装的实际包目录应从 profile 的 node_modules 解析。

### A07 / P2：所谓原子写存在并发临时文件名碰撞

位置：`lib/core.js:64`。

临时名由目标路径、pid 和毫秒时间组成。同一进程在同一毫秒并发写同一个文件时，两次操作复用临时名。

隔离复现：固定两次操作的 `Date.now()`，并发调用真实 `atomicWriteFile()`，一条成功，另一条 `ENOENT`。固定时间仅用于模拟同毫秒调度，真实运行也可能遇到同一条件。

修复：临时名使用随机唯一值并独占创建；明确同一文件写操作的串行化和最后写入语义，保留原子替换。

### A08 / P2：Node 版本承诺与实际依赖不符

位置：`package.json:91`，`lib/redteam/store-core.js:8`，`lib/redteam/schema.js:1`。

包声明 Node >=18，随包必载的演练台数据层却静态导入 `node:sqlite`。Node 18/20 没有这个内置模块。

影响：用户即使满足声明的版本范围，也可能在加载演练台时失败。本轮只在 Node 24 上运行，没有伪称做过多个 Node 版本的实测。

修复：选定并实测实际支持的 Node/Electron 内置 Node 版本，再修改 engines 和文档；如保留旧 Node，必须提供数据层兼容实现。

### A09 / P2：规则写操作允许 GET

位置：`lib/index.js:2419`、`:2429` 及 `handleRulesOp()` 的 delete/activate/reset 分支。

GET/POST 共用 op 分发，未按操作限制方法。用原始 handler 片段和模拟删除回调复现：GET 可触发 `deleteRule()`，响应 200。

影响：读取类请求能修改/删除状态，容易被误操作、预取或错误客户端触发；跨来源利用还取决于这组路由自身的来源检查，不能把它与演练台接口的校验混为一谈。

修复：列出只读 op，写操作仅接受 POST；在方法检查前禁止写 last-cwd 等状态，前端与命令入口同步调整。

## F01：自维护前必须处理的更新与发布归属
